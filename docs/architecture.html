文字修仙 · 框架架构说明

纯 Python 标准库 · 依赖单向 ui → systems → core → config · 玩法可插拔

一、分层结构

表现层 ui/panel.py 渲染ui/cli.py 命令循环
▼ 只读游戏状态，不含规则
玩法层 systems/combat 斗法 systems/tribulation 渡劫 systems/sect 门派 systems/equipment 装备 systems/arts 功法 systems/alchemy 丹道 systems/dungeon 秘境 systems/quest 任务 systems/market 坊市 systems/skill 技能
▼ 订阅事件总线，注册命令与自定义效果
内核层 game 时间·编排cultivation 修炼突破 event 剧情inventory 背包 effects 效果save 存档 attributes 属性cultivator 角色
▼ 只依赖数据定义
数据层 config/realms 境界config/items 物品 config/arts 功法config/recipes 丹方 config/dungeons 秘境 config/skills 技能 data/events.json 剧情
内核不知道玩法系统的存在。装、卸玩法只改 factory.default_systems() 一行。

二、模块职责

境界体系
config/realms.py

九个大境界、每层小境界、修为需求曲线、跨境界成功率、寿元、地点灵气浓度。

属性面板
core/attributes.py

最终值 =(base + Σadd) × Πmul。装备、功法、丹药 buff、门派加成统一走 Modifier。

修士实体
core/cultivator.py

境界、修为、气血灵力精力、背包、状态标记。只存状态，不写规则。

修炼与突破
core/cultivation.py

吐纳产修为、精力约束、顿悟；小境界与大境界两套突破判定，失败反噬。

效果执行器
core/effects.py

声明式 DSL，事件、丹药、掉落共用。支持注册自定义效果类型。

剧情事件
core/event_system.py

按地点事件率抽事件，校验触发条件与选项前置，结算效果。

背包与丹药
core/inventory.py

物品增删查、服用、丹毒累积（丹毒越高药效越弱）。

世界与编排
core/game.py

时间推进、跨日结算、寿元判定、系统装配、事件总线、命令聚合。

存档读档
core/save.py

JSON + 版本号 + 迁移表 + 原子写入；RNG 状态一并持久化。

可插拔基类
core/base_system.py

GameSystem + 事件总线 + Command 描述，是新玩法的接入契约。

三、核心循环

1 修炼cultivate(h) → 修为增长，消耗精力，推进时间
2 突破修为圆满 → 广播 → 掷骰 → 跃迁或反噬
3 机缘explore → 抽事件 → choose → 结算效果
4 斗法事件或 hunt 触发 → 回合制 → 掉落与贡献
5 沉淀rest 恢复、嗑药、save 存档
突破是唯一的高风险节点：掷骰前广播 before_breakthrough， 丹药加成、天劫拦路、门派护法都在这里介入。

四、关键接口

# 开新档 / 读档
game = create_game(name="李青玄", seed=42)
game = load_game(slot=1)

# 修炼与突破
cult = game.system("cultivation")
cult.cultivate(4)          # 吐纳 4 小时
cult.breakthrough()        # 冲击下一境界
cult.success_rate(is_major=True)   # 只读推演成功率

# 事件
ev = game.system("event")
ev.trigger(force=True)     # 外出探查（force 强制触发）
ev.choose(1)               # 选择第 1 个选项

# 效果 DSL（事件 JSON 与物品表通用）
{"type": "exp",  "value": 260}
{"type": "attr", "key": "physique", "value": 2}
{"type": "item", "id": "spirit_water", "count": 1}
{"type": "buff", "id": "spring", "name": "灵泉洗髓", "hours": 96,
 "mul": {"comprehension": 1.15}}
{"type": "battle", "tier": "normal"}     # 战斗系统注册的自定义效果

# 时间、世界、存档
game.advance_time(6)                 # 推进 6 小时，跨日自动结算
game.travel("落云山脉")
SaveManager().save(game, slot=1)

五、事件总线（扩展的主入口）

主题时机可被修改的字段

after_breakthrough突破结算后—
day_end每日跨日—
hour_passed每次时间推进—
event_resolved事件选项结算后—
combat_victory战斗胜利—
new_game / loaded开档 / 读档完成—

六、新增一个玩法系统的五步

1继承 GameSystem，定义 id 与 name
2在 on_bind() 里订阅关心的主题
3实现 commands() 暴露玩家命令
4实现 to_dict() / load_state() 做持久化
5在 factory.default_systems() 加一行
加剧情只改 data/events.json；加境界只改 config/realms.py； 加物品只改 config/items.py——都不需要动代码。

七、验证结果
