# 文字修仙 —— 可扩展修仙文字游戏框架

纯 Python 标准库实现，无第三方依赖。目标不是做一个完整的游戏，而是搭一套**能长出来**的骨架：
境界、属性、修炼、突破、机缘、丹药、存档七个基础模块已经跑通；战斗、渡劫、门派、装备、功法、技能、炼丹、秘境、任务、坊市作为「可插拔系统」示范接入方式。
境界已扩展为**凡界九境 + 仙界九境**（渡劫圆满飞升人仙，飞升不是终点——法无止境，仙是修不完的）。
定位挂机养老：**闭关挂机**（`idle` 自动打坐-休息循环、CLI 空回车即打坐）+ **离线收益**（读档按真实流逝时间结算，收益与手动打坐完全一致）。

## 快速开始

```bash
./run.sh                          # 一键启动（自动选 Python 3.10+，交互模式）
./run.sh web                      # Web 版：手机/电脑浏览器试玩（同网访问）
./run.sh --name 李青玄            # 自定义角色名
./run.sh demo.py                  # 无交互演示核心循环（固定种子，可复现）
./run.sh -m unittest discover -s tests -v   # 251 项内核回归测试
```

> 本机已通过 Homebrew 提供 `python` 命令（3.14.5，指向 `python3`），直接 `python main.py` 即可；若换机器遇到 `command not found` 或语法错误，用 `run.sh` 自动挑选 Python 3.10+（macOS 自带 `/usr/bin/python3` 是 3.9，不支持本项目语法）。

手动指定解释器（需 Python 3.10+，用到 `X | Y` 类型语法）：

```bash
python main.py --name 李青玄     # 进入交互模式
python main.py --load 1          # 读取 1 号存档
python demo.py                   # 演示
```

## 核心数据结构

```python
# 属性：最终值 = (base + Σadd) × Πmul
Modifier(source="buff:悟道", add={"comprehension": 3}, mul={"comprehension": 1.3}, hours_left=72)

# 修士：大境界 + 层 + 当前层修为进度
Cultivator(realm_key="qi_refining", stage=2, exp=47.5, total_exp=...)

# 事件：条件 + 权重 + 选项（选项带前置条件与效果）
EventDef(id, title, text, weight, conditions, choices=[ChoiceDef(id, text, effects, require)])

# 效果（dict 形式，事件 JSON 与物品表共用）
{"type": "exp", "value": 260}
{"type": "attr", "key": "physique", "value": 2}
{"type": "item", "id": "spirit_water", "count": 1}
{"type": "buff", "id": "spring", "name": "灵泉洗髓", "hours": 96, "mul": {"comprehension": 1.15}}
{"type": "battle", "tier": "normal"}     # 由战斗系统注册的自定义效果
{"type": "art", "id": "qingxin", "proficiency": 150}   # 由功法系统注册，用于传功
{"type": "recipe", "id": "cleansing_pill"}             # 由丹道系统注册，用于传丹方
{"type": "dungeon", "id": "luoyun", "floor": 2}        # 由秘境系统注册，直接送入某层
{"type": "poison", "value": -15}         # 清毒丹：负的丹毒即化毒
```

## 装备与功法

两者共用同一套机制：**挂载 → 注入 Modifier → 按 source 前缀幂等重建**。

```
最终属性 = (base + Σadd) × Πmul

穿青锋剑   -> add_modifier(Modifier(source="equip:weapon", add={"atk": 6}))
卸下       -> remove_modifier("equip:weapon")
主修清心诀 -> add_modifier(Modifier(source="art:main", add={"max_mp": 12}, mul={"comprehension": 1.09}))
```

因为战斗、修炼、渡劫读的都是 `p.atk` / `p.max_hp` 这类派生属性，装备与功法**不需要任何适配代码**就自动生效。前缀（`equip:` / `art:`）的意义在于读档后可以整批清掉旧修正器再按存档重建，避免残留。

**六个部位**：兵器、护甲、靴履、佩饰、腰带、法宝。同部位换装自动卸下旧的回背包；越阶装备（如玄铁重剑需筑基）穿不上。

**熟练度缩放**：功法到手只有六成效力，练满才十成。

```
add_effective = add × (0.6 + 0.4 × 熟练度/上限)
mul_effective = 1 + (mul - 1) × (0.6 + 0.4 × 熟练度/上限)
```

熟练度由打坐（订阅 `practice`）与斗法取胜（订阅 `combat_victory`）累积，也可以 `art practice` 专修。高阶功法 `practice_gain` 更低——天阶大衍周天诀 ×0.5，练成耗时是黄阶清心诀（×1.4）的三倍多，形成「早换早受益」与「高阶后劲足」的取舍。

## 技能（功法的主动技能）

**修习功法即得该功法的签名技能**，威力按这门功法的熟练度缩放——刚学会六成，练满十成，与属性加成共用同一条 `proficiency_scale`。所以「换更强功法」不等于立刻变强，取舍逻辑前后一致。

| 功法 | 签名技能 | 类型 | 消耗 | 冷却 | 满熟练威力 |
|---|---|---|---|---|---|
| 清心诀 | 清心咒 | 疗伤 | 灵力 18% | 3 回合 | 回复气血 22% |
| 庚金剑诀 | 庚金一击 | 攻伐 | 灵力 10% | 2 回合 | 190% 普攻 |
| 玄龟镇海功 | 玄龟护体 | 护体 | 灵力 12% | 2 回合 | 减伤 45% |
| 赤焰焚天诀 | 焚天斩 | 攻伐 | 灵力 16% | 4 回合 | 260% 普攻（自伤 6% 气血） |
| 太虚养神功 | 太虚回灵 | 回灵 | 不耗灵力 | 5 回合 | 回复灵力 28% |
| 大衍周天诀 | 周天星斗 | 攻伐 | 灵力 20% | 3 回合 | 290% 普攻 |

**为什么是「自动施法 + 策略预设」而不是回合手动选技能**：`fight(enemy) -> list[str]` 是非交互式契约，一次调用打完全场返回日志，调用方有四处——事件 `{"type":"battle"}`（自动开战，无处输入）、`hunt` 命令、`dungeon.next()`、测试与推演脚本。改成回合手动会让这四处全部失效。因此决策权交给玩家预设的**策略**，战斗仍是一次调用打完。

三档策略的差别全在「什么时候舍不得」：

| 策略 | 治疗线 | 护体线 | 灵力保留 | 推演表现（seed=2026，400 日） |
|---|---|---|---|---|
| 保守 | 气血 55% | 70% | 留 40% 不动 | 零战死，但 ~2% 的战斗打满 40 回合仍未分胜负 |
| 均衡 | 35% | 45% | 留 20% | 战斗比无技能快约 15%，无战死 |
| 激进 | 25% | 不放护体 | 倾泻 | 结束最快，但推演中出现过 1 次战死 |

**消耗与产出一律按比例，不写绝对值。** 灵力上限跨五个数量级（开局 40 → 炼气 220 → 渡劫 1173 万），写 `mp_cost=20` 在炼气是 9% 的蓝条、到渡劫只剩 0.0002%——和「灵石挂在指数增长量上结余 288 亿」「秘境修为写固定值在炼气能飞升」是同一类坑。按比例后实测庚金一击在九个境界都恰好是蓝条的 10.0%。

**回灵不耗灵力**是刻意的：它是「灵力见底」这个死局的出口，代价是让掉一回合，所以必须恰好在最需要的时候能放出来。

**残血时不放护体**（任何策略）：敌人快死了，减伤救不了你，多点输出才能结束战斗。不这么处理，保守档会一路护体到打满 40 回合。

**满血不放疗伤**：攻击技能都在冷却时，若八成药力落不进去（会溢出）就宁可普攻，否则日志里会出现「气血回复 1（60/60）」这种白让一回合的操作。

**技能系统是可选装配的**：战斗侧只做 `game.systems.get("skill")`，取不到就完全按原样普攻。卸掉技能系统后，事件自动战斗、秘境推进、既有测试与推演脚本行为分毫不变（有专门的测试守着这条）。

## 文字质感（文字即玩法）

本作的核心不是「用文字凑合出画面」，而是**让文字本身成为乐趣**：数值与判定是骨架，文案是血肉，且两者严格分离——换文风只改数据层，不动一行逻辑。

**战斗日志叙事化。** 战斗不再是「你击中 青纹狼，造成 12 点伤害」的数值简报，而是每回合从词库抽一个动作前缀组成的叙事流：

```
寒光乍现，你击中 青纹狼，造成 13 点伤害，剩余 30
你施展【庚金一击】，一道庚金剑气凝于剑尖，锐啸破空，直贯 青纹狼 要害。青纹狼 受到 22 点伤害，剩余 0
青纹狼 发出一声悲鸣，缓缓倒地不起。
```

词库（`systems/combat.py` 顶部 `PLAYER_STRIKE_FLAVOR` / `ENEMY_STRIKE_FLAVOR` / `VICTORY_LINES` 等）可自行扩充，加条目即生效。

**技能施放文案在配置里。** 每门签名技能的施放描写写在 `config/skills.py` 的 `cast` 字段，attack 类支持 `{enemy}` 占位（`str.format` 渲染）。第三方/事件发放的功法若没配 `cast`，自动退回通用句式，战斗不受影响。

**境界铭文。** 每踏入一个大境界，突破日志里多一句该境界的意境描述（`config/realms.py` 的 `REVELATIONS`，凡九 + 仙九共十八句全齐）：「金丹碎裂，一道元婴自识海踏出，从此夺舍避死、神通自成。」小境界升级不打扰。渡劫圆满突破人仙有专属横幅「霞光万道，天门洞开」，铭文即飞升叙事。

**锚点词约束（这条是测试守着的）。** 文案可以随便改，但保留几处机器依赖：普攻行含「你击中」、技能行含「施展【」、受击行含「反扑/受到/剩余」、胜利行含「倒地不起」——demo、推演脚本、自动化测试都靠它们辨认行为。词库与文案消耗的是**与战斗判定同一个随机源**，因此同 seed 输出依旧完全可复现；文风改造不改变任何数值公式与判定规则。

## 丹道（炼丹）

闭环是 **采药 → 换购丹方 → 开炉 → 成丹（分三品）**。没有采药，炼丹就是无米之炊，所以 `dan gather` 是这个系统的上游。

**成功率**（每次开炉都把算式打在日志里，不藏黑箱）：

```
成功率 = 夹在[5%, 95%]( 丹方基础
                    + 造诣 × 2%              ← 上限 12 点，即 +24%
                    + (悟性 − 10) × 1.5%
                    + 气运 × 0.4%
                    + 丹炉加成 )             ← 紫砂药鼎 +6% / 朱雀丹炉 +12%
```

**品阶**由「火候」而非二段掷骰决定：掷点低于成功率即成丹，低得越多火候越足。

```
品质值 = (成功率 − 掷点) / 成功率  +  火候修正（造诣 × 2% + 丹炉，上限 +20%）
品质值 ≥ 66% → 上品（药力 140%）　≥ 33% → 中品（100%）　否则下品（70%）
```

分工是刻意的：**成败看悟性气运，火候看手艺与家伙**。若品阶只由归一余量决定，那它必然均匀分布，造诣与丹炉就只剩「少废几炉」的意义了。零造诣无丹炉时三品各占三分之一；练满配朱雀丹炉后上品过半、下品近乎绝迹。

品阶不手抄三份表——`config/items.py` 只写中品基表，下品/上品用 `dataclasses.replace` 程序化派生（id 带 `#low` / `#high` 后缀），药效、丹毒、价格、突破加成按倍率一起缩放。**中品即基表 id 不变**，老存档与掉落表完全兼容。

**不炸炉**：失手只损材料（每种退回一半，向下取整），不损装备、不掉修为境界、不伤气血，但精力灵力照耗、时间照走。失败也给三成修为和 0.4 点造诣——「虽未成丹，火候上总算有了点心得」。

**丹毒与清毒丹**：上品药力猛、丹毒也重（140%），嗑得越猛药效越差（最低保留 30%）。清毒丹方不进药力专化丹毒，是这套负反馈的泄压阀。

## 秘境（秘境探索）

五座秘境按境界门槛依次解锁：**落云秘境**（炼气）、**万兽深渊**（筑基）、**太虚洞天**（金丹）、**瑶池仙园**（人仙，飞升后第一个仙界秘境）、**万劫云海**（金仙）。形态是**线性层数推进**——每层随机抽「妖兽 / 机缘 / 遗宝 / 静室」四种签，最后一层固定守关之敌，击倒给一次性厚赏并进入冷却。

**难度靠 tier 不靠层数**。敌人属性按玩家境界等比缩放（`combat.spawn`），所以「第 7 层」和「第 1 层」若同 tier，打起来一样难。秘境难度只由层内 `tier`（weak → normal → elite → boss）拉开，层数只是 tier 的载体。

**四条规则**：

1. **层内抽签** —— 每层按权重抽类型；机缘层走 `EventSystem` 且限定 `scene: dungeon`，不会在洞天里撞见「宗门招徒」这类户外事件
2. **进度可续** —— `dungeon flee` 随时退出，回来 `dungeon enter` 从原层继续；通关后按冷却日数方可再入（也可 `dungeon abandon` 放弃进度换取提前重入）
3. **战败退一层** —— 濒死护持后被打退一层，已得之物不吐出来，不掉装备境界；退层即整备（回 25% 气血），防残血连败的死亡螺旋；连败三次明说「此处非你眼下能撼动」
4. **奖励走效果 DSL** —— 宝箱与通关大奖复用 `core/effects.py`，修为一律用 `exp_ratio`（按当前境界需求比例）而不是绝对值——写固定值在炼气期能直接飞升、到渡劫期等于零，和「灵石挂在指数增长量上」是同一类坑

**战场在秘境里会失真**：`fight()` 只返回日志、不返回胜负，秘境靠订阅 `combat_victory` 总线标记胜负；战后气血低于 11.5% 判「败退」而非「平局」。精力门槛在深入前自己先查——`fight()` 缺精力会直接 return 且敌人满血存活，会被误判成战败退层。

## 飞升与仙界（飞升不是终点）

凡界九境（炼气 → 渡劫）之后直接接**仙界九境**（人仙 → 地仙 → 天仙 → 玄仙 → 金仙 → 太乙 → 大罗 → 准圣 → 混元），渡劫圆满突破即**飞升**——仙界就是 `config/realms.py` 里追加的九行数据，渡劫的 `next_realm` 天然指向人仙，突破路径零特殊分支，只有横幅与铭文是专属的（「霞光万道，天门洞开——你飞升仙界！」）。

```
凡界：炼气九层 → 筑基 → 金丹 → 元婴 → 化神 → 炼虚 → 合体 → 大乘 → 渡劫
       ↑ 金丹以上跨境界突破先渡天劫
飞升：渡劫圆满 → 【霞光万道，天门洞开】→ 人仙初期
仙界：人仙 → 地仙 → 天仙 → 玄仙 → 金仙 → 太乙 → 大罗 → 准圣 → 混元
       ↑ 跨境界继续渡劫，名目随境界分层（仙劫 → 天衰之劫 → 道心劫 → 斩三尸 → 合道大劫）
```

**仙劫分层**：仙界跨境界突破沿用渡劫机制（同一条 `before_breakthrough` 判定），劫名按目标境界数据驱动（`RealmDef.tribulation`）——低阶仙境渡「仙劫」、天仙起「天衰之劫」、金仙起「道心劫」、大罗进阶「斩三尸」、准圣→混元「合道大劫」。机制只换文案与名目，判定、失败拦截、劫余 buff 全部复用。

**仙界修炼产出与顿悟**：修炼产出在仙界每境 ×3（凡界 ×1.6），仙界「仙缘」更盛——顿悟比例 8% → 12%。顿悟按**每 4 时辰判定一次**（不再是一次打坐一骰）：挂机 `cultivate(24)` 与手动 `cultivate(4)×6` 收益一致，操作粒度不产生 6 倍差。

**寿元是纯展示**：挂机养老定位，`age` 随年增长、寿元随境界提升，但**不因寿元耗尽而陨落**（game.py 不判定死亡）。仙界寿元写「与天同寿」级大数。

**仙界内容（第二十五批填坑）**：凡界 24 批打磨完后，仙界是「数值衔接但内容空白」的断层——境界/神通/铭文/劫名都有，唯独缺配套。本批补齐：

| 仙界内容 | 说明 |
|---|---|
| **仙界秘境** | 瑶池仙园（人仙起步，5 层）、万劫云海（金仙起步，5 层）；守关/宝箱奖励全走 `exp_ratio`（按仙界需求比例，防后期归零），灵石锚定入门境界一场战利量级 |
| **仙阶功法** | 太虚剑典（攻伐）/ 周天妙法（挂机修炼）/ 破虚诀（突破）/ 混元一气诀（全能，太乙起）；走已预留的「仙 480」品阶预算，`validate_balance` 自检 |
| **仙界地点** | 瑶池（灵气 ×4.5）、万劫云海（×6.0），带 `min_realm` 门槛，飞升前 `travel` 被拦，防白嫖高灵气 |
| **仙界丹药** | 蕴仙丹（修为 8% 需求）/ 破境仙丹（突破 +15pp~6pp，跨全仙界 9 境）；配套 2 张仙阶丹方 + 仙材（仙兽内丹/仙草） |
| **仙阶装备** | 六部位，`min_realm="human_immortal"`，掉落池按境界自动筛（人仙/金仙 6 件，炼气 0 件） |

## 现实时钟：全程跟现实时间走（挂机也一直打坐）

**时间模型**：手动操作时游戏内时间由命令推进（一次打坐 = 游戏内 4 时辰，现实 1 秒）；但只要超过 1 分钟没操作，**现实时钟接管**——命令间隙流逝的现实时间在下一次命令前自动结算为闭关打坐。挂着不动也一直打坐，回来敲任意键即看到收益。

**后台周天运转（被动修炼）**：做任何事时，游戏时间每推进一点都会自动涨修为——打怪、探秘境、赶路、炼丹、休息期间周天自行运转，**不占精力、不打断操作、无日志刷屏**。产出为主动打坐的 60%（`PASSIVE_RATIO`），无顿悟、无功法熟练度——主动打坐/闭关仍是高收益路径（100% + 顿悟 + 熟练度）。

| 路径 | 产出 | 额外收益 | 精力 |
|---|---|---|---|
| 后台周天（做其他事时） | 主动打坐 × 60% | 无 | 不消耗 |
| 主动打坐 / 闭关 / 现实时钟结算 | 100% | 顿悟 + 功法熟练度 | 消耗 |

| 场景 | 换算 | 倍率 |
|---|---|---|
| 在线挂机（开着终端不操作） | 现实 1 小时 = 游戏内 **1.5 日** | `ONLINE_DAYS_PER_HOUR=1.5`（活跃加成） |
| 离线（关掉游戏） | 现实 1 小时 = 游戏内 **1 日** | `OFFLINE_DAYS_PER_HOUR=1.0` |
| 单次结算上限 | 24 现实小时（防挂机一年回来满级） | `CLOCK_MAX_HOURS=24` |

**闭关**：`idle [天数]` 一条命令自动推演「打坐 → 精力耗尽 → 休息 → 继续」循环，支持小数天（`idle 0.5` = 12 时辰），收益与手动 `cultivate` **完全一致**（同一套函数，无任何额外加成或折扣——「收益不区分」是硬约束）。无参 `idle` 闭关到**修为圆满自动停**——突破是决策点，留给玩家，不自动冲关、不自动嗑药。

```
> idle 5
=== 闭关 5.0 日 ===
静心吐纳，修为 +2432（0 -> 2432）
```

**CLI 空回车 = 自动打坐 4 时辰**：在线挂机连按回车即持续修炼；挂机超过 1 分钟回来，回车前会自动结算现实时间的闭关收益（见上表在线倍率）。单次闭关上限 30 游戏日（`IDLE_MAX_DAYS`，idle 最终兜底）。

**离线收益**：存档记录 `saved_at` 时间戳，读档时按真实流逝时间结算（倍率 1.0）。读档即可看到「离线归来：阔别 X 时辰」+ 闭关日志。结算后立即刷新存档时间戳，**同一存档反复读档不会重复结算**。

```
—— 离线归来：阔别 2.0 时辰 ——
=== 闭关 2.0 日 ===
静心吐纳，修为 +18698（0 -> 18698）
期间顿悟 2 次，妙悟自生。
```

离线期间修为满了同样停在突破门槛前（不自动冲关）。闭关/离线打坐期间功法熟练度照涨（订阅同一 `practice` 主题）。全部倍率在 `factory.py` 顶部可调。

### 收益时钟互斥规则（v2 重构）

同一时刻只有一种主收益在结算，多套收益**不叠加**：

| 场景 | 结算什么 |
|---|---|
| 离线期间 | 只结算离线收益（`需求 × 1.0% / 现实小时`，所有加成只生效 50%） |
| 在线但不动 | 被动周天 + 现实时钟同时存在，取高者（现实时钟走闭关，收益更高） |
| 主动打坐 / 闭关 | 暂停被动周天，改结算主动收益（100% + 顿悟 + 熟练度） |
| 战斗 / 探索 / 炼丹等操作 | 被动周天继续静默运行 |

**待领池防跳级**（`core/offline.py`）：待领池上限 = 当前层需求 100%，超出部分按 30% 自动转化为灵石；领取后超出当前层需求的部分衰减为 30%——离线收益是「辅助」，不会直接填满一整层，防止攒离线跳级。

## 日常任务（7 项 · 全可跳过）与一键托管

**日常系统**（`xiuxian/systems/daily.py`，命令 `daily list`）：7 项轻量日常，**全部可跳过，不做没有任何损失**，做了给锦上添花的奖励：

## 修炼产出：按本层需求比例

打坐、闭关、被动周天共用同一套产出公式，**以「当前层需求的比例」为基准**：

```
每时辰产出 = 本层需求 × 0.2% × 悟性倍率 × 灵气密度 × (1 + 神通加成) × 随机[0.88, 1.14]
悟性倍率   = (1 + 悟性/50) / 1.5     # 悟性 25 时为 1.0
顿悟       = 每 4 时辰判定一次，给本层需求的 8%（凡界）/ 12%（仙界）
```

**为什么不是固定速率**：旧公式按境界序号 ×1.6/×3 增长，而需求按 ×6~10 增长，增速不匹配导致
比值每境衰减约 6.7 倍——炼气期一次打坐直接打满（108%），渡劫之后形同虚设（0.00008%）。
改为按需求比例后，打坐在任何境界都有稳定意义，且与需求曲线天然同步。

| 地点灵气 | 打坐 16.7 时辰（100 精力） | 每层约需 |
|---|---|---|
| 青石镇 ×1.0 | 需求 6.6% | ~10 游戏日 |
| 宗门灵脉 ×3.0 | 需求 13.5% | ~5 游戏日 |

## 精力 = 主动操作频率闸门（v2 放宽版）

v2 定位「主动操作是调味料，挂机收益才是主菜」——精力不再是硬预算，而是**限制主动操作频率**的软闸门：

| 规则 | 数值 | 说明 |
|---|---|---|
| 精力上限 | 100 | 上限固定 |
| 恢复速度 | **2 / 时辰** | 在线离线均恢复；调息、跨日、离线结算都会回 |
| 主动打坐消耗 | **1.5 / 时辰** | 打坐不再是精力大户，可长时间挂机修炼 |
| 猎妖 / 论道 / 探索 | **8 / 5 / 10** | 主动操作的主要消耗 |
| 炼丹 / 秘境深入 | **6 / 炉、12 / 层** | 单次操作成本 |
| 突破 | 30 | 需要状态达标 |

**核心原则（v2）**：
- 精力用完后，**被动周天与离线收益不受影响**——精力只限制主动操作频率，不限制挂机收益
- 完成全部 7 项日常约消耗 40-50 精力，非常充裕；上线精力大概率是满的（离线也恢复）
- 闭关挂机 `idle` / 一键托管 `idle-auto` 走挂机路径（角色自行打坐-休息），不受精力约束

**突破的三重门槛**（突破本就需要达标，不是随时能冲）：
1. **修为达标**——当前层修为必须满（`exp ≥ exp_required`，面板显示「修为 100/100」才能冲击）
2. **成功率判定**——比例式公式（境界 base × 三维倍率 − 丹毒 + 加成，各来源封顶 +30pp），失败温和化：只散当前层 20%~40% 修为 + 轻伤（调息 4 时辰可愈）+ 失败补偿 +2pp（可叠加至 +10pp），**绝不掉境界**
3. **金丹以上先渡劫**——天劫/仙劫未过直接拦截，另加 3 日调养冷却

所以「一直点按钮推进」的节奏是受控的：修为要攒够（时间成本）→ 突破要掷骰（失败成本）→ 仙界还要过劫。

## 功法系统（多件装备 + 数据驱动效果）

### 数据结构

```python
@dataclass(frozen=True)
class ArtEffect:                # 一条效果（数据）
    type: str                   # 效果类型，见 EFFECT_TYPES
    value: float = 0.0          # 数值（attr_mul 为偏移 0.15=+15%）
    key: str = ""               # 属性键（attr_add / attr_mul 用）
    params: dict = {}           # 新类型的自定义参数，无需改结构
    stack: str = ""             # 可选：覆盖该类型的默认叠加规则

@dataclass(frozen=True)
class EffectTypeDef:            # 效果类型的元信息（数据驱动的核心）
    stack: str                  # add 相加 / mul 相乘 / max 取最高
    desc: str                   # 说明（面板展示）
    unit: str                   # "" 或 "%"
    cost: float                 # 每单位折算的「效果点」，用于品阶预算

@dataclass(frozen=True)
class ArtDef:
    id, name, rank, desc
    price, min_realm            # 学习条件：灵石 + 境界门槛
    effects: tuple[ArtEffect]   # 效果列表（可多类型混搭）
    max_proficiency, practice_gain, level_growth, skills
```

### 效果类型与叠加规则

| 类型 | 含义 | 叠加规则 | 消费端 |
|---|---|---|---|
| `attr_add` | 属性固定值加成 | add（相加） | 属性管线（Modifier） |
| `attr_mul` | 属性百分比加成 | add（**偏移相加**，非连乘） | 属性管线（Modifier） |
| `cultivate_speed` | 打坐修为速率 | add | `cultivation._hourly_gain` |
| `breakthrough_rate` | 突破成功率 | **max（取最高）** | `cultivation.success_rate` |
| `insight_rate` | 顿悟（悟道）概率 | add | `cultivation` 顿悟判定 |
| `stone_gain` | 灵石获取 | add | `combat._stones_for` |

百分比刻意按**偏移相加**而非连乘：两件 +20% 得 +40%（×1.4）而不是 ×1.44 —— 多件功法不会叠成指数爆炸。
突破率用 **max**：突破是决策点，功法只该「略微增加把握」而非抹平难度。强效类型另有封顶
（`BONUS_CAPS`：速率 ≤60%、突破率 ≤6%、灵石 ≤50%、悟道 ≤15%）。

### 品阶、等级、学习条件、装备上限

| 项 | 规则 |
|---|---|
| 品阶 | 黄阶/玄阶/地阶/天阶/仙阶，每阶有**效果点预算**（`RANK_BUDGET`，按练满后计价），由 `validate_balance()` 自检、测试守着 |
| 等级 | 由熟练度派生：每 200 熟练度 1 级（满级 5），每级效果 ×`level_growth`（+15%） |
| 熟练度 | 决定「发挥几成」：0.6（刚会）→ 1.0（练满），换高阶功法不等于立刻变强 |
| 学习条件 | `price`（灵石）+ `min_realm`（境界门槛） |
| 装备上限 | `slots_for_realm()`：炼气起 2 件，每 3 个大境界 +1，硬顶 5 件 |

平衡预算（练满后计价）：黄阶 32 / 玄阶 90 / 地阶 240 / 天阶 260 / 仙阶 480 点；
折价：固定值 1 点/点、百分比 1 点/%、速率 2 点/%、悟道 2.5 点/%、突破率 3 点/%。

**实测平衡**（练满 + 装备，宗门灵脉）：

| 配置 | 攻击 | 气血 | 打坐产出 | 速率 |
|---|---|---|---|---|
| 筑基·黄阶 2 件 | +35% | — | +5% | 0% |
| 金丹·玄阶 2 件（攻防） | +70% | +3% | 0% | 0% |
| 元婴·地阶×2+天阶 3 件 | +19% | +43% | +79% | 60%（封顶） |

属性加成只影响观感与成长感 —— 敌人按玩家属性等比缩放，战斗难度自洽。

### 固定值加成的境界缩放

固定值若写死，前期占比过大（+67%）、后期形同虚设（+0.003%）。因此 `realm_attr_scale()`
**从境界配置累加出量级比**（该境界累计攻击 / 炼气累计），不写死系数 —— 改任何境界配置都自动跟随，
实测每件的固定值加成都稳定在基础属性的约 +13%。

### 实时重算

`ArtSystem.rebuild()`：移除旧 `art:` 前缀修正器 → 按类型聚合所有已装备功法的效果 → 经
`EFFECT_APPLIERS` 落地（属性类进 Modifier，速率类进缓存）→ 夹住当前气血/灵力不超过新上限。
装备/卸下/熟练度变化/读档都会触发，因此「装卸即时生效」。

### 如何新增一种效果类型（以「突破成功率」为例，三步，核心逻辑零改动）

```python
# ① config/arts.py —— 声明类型（叠加规则、说明、平衡折价）
EFFECT_TYPES["breakthrough_rate"] = EffectTypeDef(STACK_MAX, "突破成功率加成", "%", cost=3.0)

# ② systems/arts.py —— 注册「聚合值如何生效」（非属性类用通用函数即可）
EFFECT_APPLIERS["breakthrough_rate"] = _apply_generic     # 写入 bonus 缓存（可套封顶）

# ③ 消费端 —— 读一次并参与计算（core/cultivation.py）
arts_sys = self.game.systems.get("arts")
art_rate = arts_sys.bonus("breakthrough_rate") if arts_sys else 0.0
rate = base * (...) + extra_bonus + pw_bonus + art_rate
```

之后即可在功法里写 `ArtEffect("breakthrough_rate", 0.03)` —— 聚合、装备、重算全部自动支持，
无需再改 `rebuild()` 或任何核心逻辑。

## 修仙五要（法·财·侣·地·师）

「法财侣地师」五要齐备，各自提供修炼加成，**统一走 `core/bonus.py` 全局聚合器**
（同一套效果类型与叠加规则），装卸/升级/好感/拜师即时重算。实测递进：

| 根基 | 打坐产出 | 每层耗时 |
|---|---|---|
| ① 只有功法（法） | +26% | -20% |
| ② 功法 + 洞府（地） | +55% | -36% |
| ③ + 道侣（侣） | +66% | -40% |
| ④ + 师承（师） | **+77%** | **-44%** |

**地·洞府**（`estate`）：购置 → 扩建 → 维护。品阶（凡居/洞府/福地/洞天）越高加成越强（修炼 +5%→+45%），
但每日需维护灵石——**付不起则荒废**（加成失效，补缴复灵），形成「财」与「地」的相互牵制。

**财·产业**（`asset`）：灵田/灵石矿脉/坊间丹铺/跨域商队，每日产出灵石与材料（供丹道变现）。
可增资升级（1~5 级线性成长），同样有维护费——**付不起则停摆**。产出刻意用线性而非复利，防止后期收入爆炸。

**侣·道侣**（`companion`）：结识四位道友（剑修/丹师/阵修/剑仙），加成随**情分**增长（初识五成 → 圆满十成）。
增进情分的途径：**双修**（每日 3 次，耗精力灵力换修为+情分）、并肩对敌（战斗自动涨）、**赠礼**（灵石换情分，快但纯消费）。

**师·师门**（`sect` 扩展）：**七大门派**（青云宗/血煞门/药王谷/天机阁/剑冢/万宝楼，各有独特 buff 与师长），
入门后按职位拜师（外门→长老），**职位越高，门派修炼场地加成越高**（外门+2% → 长老+12%）。
门派专属功法以**贡献兑换**（唯本门弟子可修，共 6 门：青云剑诀/血煞魔功/药王真解/天机演算诀/万剑归宗/点石成金术）。
**灵室静修**（贡献租用，24 时辰修炼 +30%）——形成「做任务 → 攒贡献 → 换功法/租灵室 → 冲关」的完整循环。

**法·功法**：见上文「功法系统」。

命令：`estate [list|buy|upgrade|restore|sell]`　`asset [list|buy|upgrade|sell]`　
`companion [list|meet|dual|gift]`　`sect [masters|apprentice|mentor|…]`　`claim`

## 修为获取途径（打坐之外的五条路）

所有途径的修为都按「**本层需求的比例**」结算（与打坐同一口径），不会因境界提升而失效；
每条途径都有独立的防刷限制，避免任何单一途径碾压其他。

| 途径 | 触发条件 | 修为收益 | 成本 | 防刷限制 |
|---|---|---|---|---|

## 离线挂机（后台累计修为）

**字段设计**（存档 JSON `offline`）：

```json
{
  "offline": {
    "last_settled_at": 1767312000.0,   // UTC epoch 秒（唯一时间基准）
    "pending_exp": 1234567.0,          // 待领修为池（无上限）
    "total_offline_exp": 98765432.0,   // 累计离线修为（统计）
    "settled_count": 42,               // 结算次数（幂等审计）
    "last_duration": 36000.0,          // 上次有效时长（秒）
    "anomaly": ""                      // 异常说明：首次登录/时间回拨/超长截断
  }
}
```

若迁移到数据库，等价表结构：

```sql
CREATE TABLE player_offline (
  player_id        BIGINT PRIMARY KEY,
  last_settled_at  DOUBLE PRECISION NOT NULL,   -- UTC epoch 秒，建索引
  pending_exp      DOUBLE PRECISION NOT NULL DEFAULT 0,
  total_offline_exp DOUBLE PRECISION NOT NULL DEFAULT 0,
  settled_count    BIGINT NOT NULL DEFAULT 0,
  updated_at       TIMESTAMP NOT NULL
);
```

**结算公式**：

```
有效时长 = clamp(now - last_settled_at, 0, 365天) - 宽限期(60秒)
修为     = 有效时长(小时) × 本层需求 × 1.0%/小时 × (1 + 神通加成)
```

离线速率 = 主动打坐的 50%（主动 ≈2%/现实时，含时间闸门打坐效率），挂机永远比不上亲自操作，
但绝不浪费时间——对齐 v2「挂机养老」核心体验。

**接口流程**（读档时自动执行）：

```
load_game(slot)
  ├─ 读存档 → Game.from_dict（恢复 offline 状态）
  ├─ settle_offline(game, saved_at)
  │    ├─ 无 UTC 基准且有 saved_at → 兼容换算（老存档）
  │    ├─ compute_offline_gain() → 处理边界（首次/回拨/超长/宽限）
  │    └─ settle() → 累加 pending_exp + 推进 last_settled_at（幂等）
  ├─ claim() → 能落袋的立刻到账，本层已满的留池等突破
  └─ manager.save() → 写回，保证重复读档不再结算
```

**边界处理**：

| 情况 | 处理 |
|---|---|
| 首次登录无记录 | 不发修为，初始化 `last_settled_at = now` |
| 时间回拨（now < last） | 不发修为，基准修正为 now，标记「时间回拨」 |
| 异常偏移（> 365 天） | 截断到上限，标记「超长截断」 |
| 短间隔（< 60 秒） | 宽限期内不结算，防抖动与刷取 |
| **幂等** | 结算后立刻推进 `last_settled_at` 并 `settled_count + 1`；重复调用 elapsed 归零 |

**待领池设计**：离线修为先进 `pending_exp` 池（总量无上限），登录时自动领取——
能落袋的立刻到账，本层已满的部分**留在池中**，突破后 `claim` 继续领取，
因此超长离线积累的修为不会因为「本层已满」被 add_exp 截断而浪费。

## 新玩法：天骄榜 & 心魔劫

### 天骄榜（排名竞技）

金丹以上自动入榜（垫底），挑战排名高于自己的 NPC 天骄（10 位，战力按境界递增），胜则互换名次。

- **每日俸禄**：按名次发放灵石与修为（第 1 名 500 灵石 + 30% 需求，逐名递减）
- **防刷**：每日 3 次挑战 + NPC 缓慢成长（防躺平）+ 敌人按属性等比缩放
- 操作：`tianjiao list` 看榜　`tianjiao fight <名次>` 挑战

### 心魔劫（心境考验）

跨大境界突破成功后 30% 概率触发（金丹起），文字三选一（正道/歧途/超脱）。
不同选择不同后果——无绝对对错，体现修仙哲学。正道稳（小增益），歧途险（大增益+副作用），超脱随机。

- **防刷**：自然触发不可主动刷；每次突破最多一次
- **数据驱动**：心魔题库在 `inner_demon.py` 的 `TRIALS` 元组中，加新题只需添一条
- 操作：突破后自动触发，`demon <选项>` 选择

## 时间预算闸门（防刷修为的核心约束）

游戏时间推进速度 ≤ 现实时间 × 10（`TIME_RATIO=10`，即 1 现实小时最多推进 10 游戏时辰）。
无论怎么点按钮，修为获取速率的上限被**现实时间**锁定。

**实现**：`core/time_governor.py` 的 `TimeGovernor` 在 `Game.advance_time()` 入口加一道预算闸门：

```
可用预算 = (now - anchor) / 3600 × 10 - consumed
实际推进 = min(期望推进, 可用预算)     # 不足则截断
```

- **闭关挂机（idle）/ 离线结算**：走 `bypass_budget=True`（挂机收益由 offline.py 的独立速率 1.0%/小时控制，不叠加时间闸门）
- **被动周天**：不走 advance_time（由 `_on_hour_passed` 被动接收时辰），天然不受闸门影响
- **主动操作**（打坐/休息/战斗/突破/秘境/历练）：全部受闸门约束

**效果**：精力预算限制了「每天能主动操作多少」，时间预算限制了「游戏时间流逝多快」。双重约束下，
修为获取速率的上限 = 现实时间 × 10 × 打坐效率 —— 刷按钮无法突破这个物理上限。

**旁路**：demo / 测试设 `game.clock.disabled = True` 跳过闸门。

## 数值防膨胀

修为/属性随境界指数增长（炼气 100 → 混元圆满 ~1.2e19），数值体系靠三层机制保持可读、可控、可解释：

**1. 大数格式化（显示层）**：所有修为与属性显示走 `numfmt.fmt_num()` 中文单位——万 / 亿 / 万亿 / 兆 / 京。面板、日志、战斗伤害统一可读：「气血 60/8000万」「修为 60亿/264.6亿」，不再出现 11 位长串。纯展示，不改任何数值与判定。

**2. 收益按比例（数值层）**：修为增长设计上就防「越大越爆炸」——
- 顿悟奖励 = 当前层需求 × 8%（凡界）/12%（仙界）：**比例恒定**，无论需求涨到多大，每层修炼天数不变，不形成正反馈膨胀
- 秘境/丹药修为走 `exp_ratio`（需求比例）而非绝对值（写固定值在炼气能飞升、渡劫等于零）
- 被动修炼 = 主动打坐 × 60%，无顿悟——只是线性附加，不放大顿悟
- 突破失败修为 -35%（比例惩罚，不随数值增大而失效）

**3. 收益有界（节奏层）**：现实时钟单次结算上限 24 现实小时、闭关上限 30 游戏日；被动修炼不耗精力、无独立公式。纯挂机基线（seed=2026）：~3000 日走完凡界全程 + 仙界五境（金仙后期），仙界每境 ~190 日与既有基线一致——新增收益渠道后节奏未失控，文档同步更新基线。

## 关键设计

**双层突破。** 小境界突破（炼气三层→四层）几乎必成只耗修为；大境界突破（炼气圆满→筑基）有失败率、可嗑丹、金丹以上还要先渡天劫。

**突破判定开放给外部。** `breakthrough()` 在掷骰前广播 `before_breakthrough`，任何系统都能往 `payload["bonus"]` 叠加成功率，或直接 `payload["blocked"]=True` 中止。丹药、渡劫、门派护法、阵法都走这条路，彼此不知道对方存在。

**突破率是比例式，不是加和式。** 旧公式 `base + 0.01×(体质−10) + ...` 在体质≥18 就被 clamp 顶格到 98%，三维差异后期完全失效。现改为：

```
成功率 = 夹[5%, 98%]( base × (1 + 0.15%×(体质−10) + 0.10%×(悟性−10) + 0.05%×(气运−10))
                      − 0.015%×丹毒 + 丹药 + 神通 )
```

三维按倍率放大多大的 base 就放大多少：大乘期（base 0.18）三维 500 时实际 0.45——属性到后期依然可解释、有贡献，不再被上限吞掉。

**效果 DSL 可扩展。** 内置类型覆盖数值、属性、物品、buff、flag；不够用时，`game.register_effect("battle", handler)` 注册自定义类型，事件 JSON 里直接写 `{"type":"battle"}`。战斗就是这样被剧情事件调用的。

**随机源可存档。** `RNG` 持久化 Mersenne Twister 内部状态，读档后随机序列无缝延续，配合固定 seed 可完整复现一局。

**敌人按玩家等比缩放。** 战斗系统不维护「每个境界一张怪物表」，而是按玩家当前属性乘以难度系数生成，从炼气到渡劫共用一套代码。

**冲关冷却。** 突破失败或被拦截（多半是渡劫未过）后需调养 3 日（小境界 1 日）才能再冲。没有这道闸，玩家可以每天硬冲大境界，而失败累积的丹毒（+3）跑不过每日消退（-1），越冲越难，最后卡死在某个境界。血量低于 40% 时突破只会预警、不会拦截——残血冲关是玩家自己的选择，但得让他知道代价。

**事件总线的日志要就地回收。** `bus.emit()` 不返回 handler 的返回值，因此凡是订阅者产生了给玩家看的文本（如「功法熟练度 78 → 104」），一律塞进 `payload["logs"]`，由广播方统一收回拼进返回日志。否则效果发生了，玩家却看不到。

## 如何扩展

**加一个新玩法（比如炼丹、秘境、双修）**

1. 继承 `GameSystem`，写上 `id` 与 `name`
2. 在 `on_bind()` 里 `self.game.bus.on(主题, 处理函数)` 订阅关心的时机
3. 需要玩家输入就实现 `commands()` 返回 `Command` 列表
4. 需要持久化就实现 `to_dict()` 与 `load_state()`
5. 在 `factory.default_systems()` 里加一行

可用主题：`new_game`、`loaded`、`before_breakthrough`、`after_breakthrough`、`day_end`、`hour_passed`、`practice`（打坐练功时，区别于任意时间流逝的 `hour_passed`）、`event_resolved`、`combat_victory`。

**加剧情**：只改 `data/events.json`，不动代码。
**加境界**：在 `config/realms.py` 的 `REALMS` 元组里加一行。
**加物品/丹药**：在 `config/items.py` 的 `ITEMS` 字典里加一项，效果用同一套 DSL。
**换界面**：重写 `ui/panel.py` 与 `ui/cli.py`，内核零改动。

渡劫裸装成功率约 45%，叠上功法、丹药、门派可推到 80% 以上。初始 200 灵石是刻意卡的线——够修习一门黄阶功法，不够买兵器，开局就要在「功法 / 门派 / 攒钱买装备 / 换购丹方」之间做取舍。

任务与坊市接入日常循环后（seed=2026 / 7，400 日，含猎妖、事件、任务、坊市）：两 seed 均第 ~244 日达渡劫后期，无崩溃；青云宗声望累积 1400+（散修声望 5）、一次性任务完成 2、进行中 3、坊市买入 40 次、卖出 85 次。**灵石有了稳定的消费出口**（买丹药补足消耗、卖妖丹/材料回流灵石），后期灵石结余从纯秘境轮的约 1.2 万量级被进一步消纳，溢出明显收敛。任务把已有行为（战斗/事件/突破）转化为可交付目标，声望跨门槛（如「宗门荣耀」需青云宗 24）后自动解锁高阶任务，形成「做任务涨声望 → 解锁更肥任务 → 再涨声望」的正循环。

技能接入日常循环后（seed=2026 / 7，含猎妖、事件、任务、坊市、六门功法全修）：两 seed 均推进到渡劫后期，无崩溃，六门功法全部修习（技能全解锁）。**技能对进度曲线没有破坏性影响**——三种策略与无技能对照组最终境界一致，差别只在战斗过程：每场平均施法约 10~12 次，均衡/激进档的战斗回合数比无技能少约 15%，保守档反而更长（治疗与护体占掉了输出回合），激进档在其中一个 seed 付出了 1 次战死。这个「更快 vs 更稳」的取舍正是策略预设要交还给玩家的东西。

仙界扩展后（seed=2026，纯挂机策略：修炼+顿悟+突破，无丹药无秘境）：第 150 日飞升人仙，431 日天仙、692 日玄仙、884 日金仙、1143 日大罗、1474 日混元，约 3000 日混元圆满——**仙界每境 130~190 日，与凡界后期同构**（顿悟按需求比例恒定所致），符合挂机养老的长线定位；全资源玩家（丹药/秘境/功法叠加）会明显更快。从渡劫后期构造玩家实测仙劫链路：天衰之劫判定 73.1% 渡劫率 → 渡劫成功 +5% → 突破独立判定，双层门槛按设计工作。

**v2 挂机养老版基线**（seed=2026，纯挂机：修炼+顿悟+突破，精力放宽后打坐不再卡时长）：154 日筑基、219 日金丹、294 日元婴、570 日大乘、738 日飞升人仙、1346 日混元、1501 日混元圆满——**精力放宽（打坐 1.5/时 + 恢复 2/时）让纯挂机节奏比方案 A 基线（约 3000 日通关）快 2 倍**。离线收益 1.0%/现实小时（对齐 v2 软上限表「离线=主动的 50%」）且加成只生效 50%、待领池封顶 1 层需求防跳级；7 项日常每日约 +5% 修为的锦上添花；突破失败温和化（散 20~40% + 补偿 +2pp）让冲关不再劝退。**注**：v2 目标表「纯离线 180-240 日飞升」与「每日 1-2 小时 90-120 日飞升」基于全资源场景，当前纯挂机（无丹药/无秘境）节奏约 170-200 日，已对齐飞升目标；筑基段（5-7 天）与飞升段在数学上不可能同时满足（比例体系下全流程等速），以飞升行为主锚。

**仙界内容基线**（第二十五批，从人仙起步纯挂机模拟，seed=2026）：跨大境界约每 25~46 日、每小境界约 6-11 日；仙界秘境/功法/丹药/装备全部数据驱动接入，守关/宝箱奖励走 `exp_ratio` 保证仙界后期不掉链子。品阶预算自检全绿；仙界秘境进/抽签/推进/通关 + 存档读档兼容均验证通过。

## 已知边界

- 战斗修为收益略高于打坐（约 1.13 倍），属风险补偿（战败会掉 20% 修为 + 灵石）；若后续失衡，调 `combat.py` 的 `exp_reward` 系数即可。
- v2 后**探索不再有凶险**（地点只影响灵气与机缘率）；连续探索 3 次后机缘率减半（疲惫值），休息 4 时辰恢复。
- 坊市每日买卖各限 3 次，交易会推动价格（防倒买倒卖套利）。
- Web 版按 Cookie 分会话；同一浏览器共享角色，换设备/无痕窗口会开新档。
- 存档为明文 JSON，改档属于单机可接受的作弊（无防篡改）。

- 装备为简版：纯属性、无强化等级、无套装效果、无耐久。
- 技能为策略自动施放，无回合内手动选技能（受 `fight()` 非交互契约限制，见上文）。
- 门派为示例实现，只覆盖入门、日俸、贡献、晋升（v2 起贡献每日自动获得）。
- 炼丹为单炉串行，无「火候自动控温」「批量一键炼到底」；丹炉占法宝位，与青囊葫芦二选一。
- 仙界九境主体内容已落地（第二十五批：仙界秘境/仙阶功法/仙界地点/仙阶丹药/仙阶装备），但**仙界专属法则系统、仙阶门派、仙界专属事件**仍是下一片空白（仙界内容目前偏数值爬坡）。
- 寿元为纯展示（挂机养老定位，无死亡判定）；仙界「与天同寿」大数。
- 闭关不自动突破、不自动嗑药（决策点留给玩家）；一键托管 `idle-auto` 同样不越权。
- 氪金设计（离线扩容/外观/一键日常）为单机版的预留方向，当前未接入付费体系——数值天花板不因付费而变，此设计红线不变。
- 无 NPC 对话树、无地图探索网格（秘境为线性层数推进，非自由地图），都可按上文方式接入。
